# 加密 agent 历史账号策略

本分支默认允许完整加密 agent 历史在合格的原生 Responses 账号之间原样续接，优先已知生产账号；原账号不可用时按普通池准入选择替代账号。保留原始密文、可读历史和已执行工具结果，不改写生产归属。

上游配置键 `gateway.disable_encrypted_agent_owner_binding` 和环境变量 `GATEWAY_DISABLE_ENCRYPTED_AGENT_OWNER_BINDING` 继续接受并透传，便于兼容现有配置；在本分支中 true/false 都不切换默认可移植策略。它们不是安全校验的总开关。

带 `previous_response_id` 的请求仍须匹配已知账号；指针归属未知、混合生产账号与指针不一致、压缩状态或路线发生变化时保守拒绝。当前请求或 WS 连接已知的归属记录随后丢失，也不能当作首次历史，不能使用旧预热帧补造本轮历史。

跨账号密文兼容由上游决定。普通身份、用户及 Key 权限、分组、模型、余额、额度、账号状态和并发检查仍在实际发送前执行。明确的发送前拒绝可沿既有 HTTP 规则重选；网络中断、取消、交付不确定、已执行工具结果和 WS 当前轮次不授权自动回放。Beta 有损省略仅在独立的管理员开关和具体发送前拒绝条件同时满足时适用，见 [409 省略加密内容](encrypted-history-409-beta.md)。

## 归属与交付

已完成的 A 历史被 B 消费后，原 A 记录不会改成 B。B 新输出先建立 pending 屏障，仅在成功的最终下游写后提交 B。存储错误、交付未确认和已有冲突继续拒绝；不清空 Redis 来绕过保护。

首次遇到且没有归属记录的完整输入沿普通准入处理。只有原生请求完成并成功交付，才能记录该账号消费完整输入的兼容性观察；这不是对原始生产账号的推断，也不授权自动重放。后续消费不能覆盖已有生产记录。

切换不同版本网关时仍须核对历史策略并排空旧 WS；上游严格版本和本分支对混合账号历史的默认行为不同，不承诺无条件滚动回退。响应指针及交付记录不因配置取值改变而失效。
