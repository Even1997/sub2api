# 优先调度缓存权重

展开「调度配置」可设置「缓存命中率权重」，所有模式均适用，范围 0–100，默认 0。旧配置按 0 读取；旧客户端省略字段时保留现值，显式提交 0 才关闭。

本分支沿用本地调度：缓存评分只使用当前请求对应模型、分组、推理强度和使用记录窗口内的成功完整请求。样本须有唯一有效 trace，排除失败、取消、未完成、图片/视频和负数 Token 计数。单次缓存率为 cache_read_tokens / (input_tokens + cache_read_tokens + cache_creation_tokens)，按请求等权平均。账号管理性能列仍展示全局性能窗口统计；两者范围不同，不能将该列直接当作调度评分输入。

缓存分数 = 平均缓存百分数 ÷ 100。保留本地质量、所选首字延迟、实时负载、成本四项评分，将缓存项加入权重总和后归一化，再应用原错误率惩罚。例：原权重总和 100、基础分 70，缓存权重 25、平均缓存 80% 时，基础分为 (70 × 100 + 80 × 25) ÷ 125 = 72。缓存权重 0 保持原评分。

样本须达到「最小样本数」。缺失、无效或样本不足使用中性分 0.5，并在启用权重时标记「缓存样本不足」；真实 0% 与无数据不同。展示颜色档位不改变连续评分，也不新增停调阈值。

Teams 固定成本回本、风险、并发/RPM、优先级、利润门禁、会话粘性和归属保护继续生效。高缓存分不能绕过准入，低缓存不会自动停用账号。配置沿用管理员 API 和设置存储，无新数据库迁移；回滚旧二进制后不使用缓存权重。

UI 将「探针轮次降智率」统一显示为「降智率」，相关入口使用「质量检测」。仍只统计完整且结论明确的检测轮次，不代表全部业务请求。保留本地默认检测间隔 30 分钟；API 字段与统计口径不因显示名称改变。
