# 永久小时消费汇总

使用记录的热力图旁新增「查看详情」。抽屉默认展示选中日期（未选单日时为今天），按小时、请求模型、计费类型汇总；可选日期与模型，沿用页面其他筛选条件。Tokens、图片张数、视频秒数/段数、请求数分别计量。金额默认显示四位小数，可切换精确金额；极小非零费用不显示成零。

小时桶使用 UTC 保存，热力图、抽屉和账单统一按北京时间（Asia/Shanghai）归日。`actual_cost` 已包含原始计费倍率，汇总不再乘倍率。余额和订阅分别展示；小时费用不减返佣。手动月账单从小时汇总计算，继续扣除当月正向返佣转余额流水，按 ¥1 = $1 站内额度折算。账单仍仅手动生成、仅导出 PDF。

## 存储与一致性

- 迁移 `321_permanent_hourly_usage.sql` 新增 `user_usage_hourly`，保留用户、小时、模型及页面已有筛选维度，不保存单次请求详情，不参与 90 天清理，也没有指向密钥/分组/日志的级联删除。
- 日志 INSERT 的 BEFORE 触发器只标记，AFTER 触发器才累计。`ON CONFLICT DO NOTHING` 不会多算；账务、日志、小时汇总处于同一数据库事务。回滚时一并回滚。
- UPDATE 按旧值扣除、新值增加；日志计费时间禁止修改，以免跨分区 UPDATE 的 DELETE/INSERT 被误认作保留期清理。保留原时间的金额/模型纠正可正常累计。
- 旧日志以 `hourly_summary_recorded=false` 标记。后台每分钟运行最多 20 秒、每批 1,000 条，使用行锁和 `SKIP LOCKED`，允许多实例、重启和失败后重试。此回填独立于 dashboard 聚合启用开关。
- DELETE 不减少历史汇总；若旧记录尚未归档，则在删除事务内补计。父表和已有分区 TRUNCATE 在存在未归档数据时拒绝执行；已归档后清空日志不影响汇总。应用分区 DROP 先锁表、检查回填完成，再在事务内删除。
- 历史完整性沿用已有 `monthly_bill_coverage` 和 `monthly_bill_missing_months`，不推断已删除记录。热力图以阴影及说明标识不完整历史；回填中标记汇总尚不完整。月账单在该月尚有未回填记录时拒绝生成。

接口：`GET /api/v1/usage/hourly-summary`，使用当前登录用户的身份，忽略客户端指定的用户 ID。小时详情最多 31 天，日热力图最多 400 天，可翻页查看更早年份。金额和详情计量通过十进制字符串传输；图表为兼容现有组件使用数值。

本次切换的是热力图、小时详情和月账单。请求列表及既有明细统计/分析接口仍受日志保留期限制，不能把这些接口当作永久财务数据源；后续汇总报表应读取 `user_usage_hourly`。

## 验收与证据（2026-10-27）

- PostgreSQL 18 独立临时 schema：分区/普通表迁移、并发回填、清理前补计、重复插入、冲突更新、回滚、金额纠正、拒绝跨分区改时间、并发提交、用户隔离、模型/厂商/分组/密钥/计费模式过滤、DELETE/TRUNCATE/DROP 后汇总不变。
- 月账单回归：回填中禁止生成，完成后恢复；清除明细后新账单与旧消费一致，返佣、订阅、版本幂等及历史快照保持原行为。
- 100,000 条请求以 1,000 条一批插入；账单生成约 4–5 毫秒，快照 3,387 字节。该数据是本机测试结果，不是生产吞吐承诺。同一小时维度的写入会争用同一聚合行；批量导入应使用有界事务。
- API 测试验证身份隔离、无登录拒绝、时区固定、日期范围与参数校验；4 项现有保留期清理回归通过。

- 完整服务端编译通过；Vite 生产构建通过（使用现有本地脚本绕过 Windows esbuild 临时映射文件删除问题，没有改依赖）。

## 上线边界

本次未部署。迁移需要为现存日志建立待回填索引，执行时长/锁等待取决于生产数据规模；上线前应在相同规模副本验证迁移时间。迁移与应用应协调更新：暂停旧版本的账单生成与日志清理，避免旧进程继续从已清理的明细计算账单或绕过新版本的 DROP 检查；全部实例切换新版本后再恢复。不要禁用归档触发器进行导入，也不要直接删除尚未归档的分区。已经删除的历史数据不能由本功能恢复。
