## Cutover incident and recovery

- The first attempt passed app, worker, public version and authentication checks. Python default HTTP transport received a Cloudflare 403 for the Main homepage, triggering the automatic rollback. Curl returned 200 for the same public URL and both green local roots. Asset validation now uses the same curl transport as the other checks and still rejects HTTP errors and HTML fallbacks for assets. The full second cutover validation passed.
- The rollback restored original routing and workers and preserved recovery files. It interrupted re-login task 4512 after that task was claimed during the first verification window; its original worker container was confirmed stopped and its stage remained `protocol_connecting`. No login request or credentials were replayed.
- The existing administrative cancellation endpoint was called once. It returned 500 after committing the task cancellation; a database read-back confirmed terminal `failed` state. The request was not repeated. Its proxy source is `account`, so there was no Mihomo lease to release.
- The cancellation response bug exists at the pre-integration main commit `770ea428587f040ec7fdb06835ed462af6127a02`: `CancelTask` returns 12 columns while the shared scanner expects 13, including `oauth_profile`. This pre-existing issue remains outside the released integration and needs a focused follow-up fix. Account credentials were not changed by cancellation.
- A later cutover attempt initially stopped at the idle-task guard without changing routes; it proceeded only after the orphan task had been finalized. First-attempt worker containers remain stopped with suffix `-attempt1-v2.21.0-20261112`.

## Rollback

The deployment script is retained as `/var/backups/sub2api/v2.21.0-20261112/deploy.sh`. Its rollback action starts and health-checks the old apps, restores Caddy routing and worker bindings, copies forward newly written worker recovery records, and drains new inbound connections. It never restores an old database dump over current production data.

```powershell
ssh ssh40 "sudo -n bash /var/backups/sub2api/v2.21.0-20261112/deploy.sh rollback"
```

Old apps are `sub2api-v2.20.0-agent-affinity-20261112` and `sub2api-mr-v2.20.0-agent-affinity-20261112`. Archived worker names have suffix `-bak-v2.21.0-20261112`. Caddy rollback file: `/etc/caddy/Caddyfile.bak-v2.21.0-20261112`.
